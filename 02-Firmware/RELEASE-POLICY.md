# Firmware release policy

## Назначение

Разделение **исходников**, **официальных файлов**, **локально собранных образов** и **резервных копий устройства** обязательно. Нельзя считать их взаимозаменяемыми.

## Состав каждого бинарного релиза

- Название образа, точный исходный файл, размер и SHA-256.
- Целевая ревизия: маркировка PCB, SoC, радиочип; совместимые альтернативы — только после проверки.
- Происхождение: ссылка на upstream/коммит, оригинальный пакет, локальные патчи; если неизвестно — явная пометка.
- Перечень компонентов (например, bootloader, kernel, root filesystem, FPGA bitstream), **только если подтверждён**.
- Известные результаты тестов: питание, USB, сеть, IIO, RX; непроверенные функции указывать отдельно.
- Способ записи, отката, восстановления; риски потери доступа и данных.
- Лицензии и условия распространения сторонних компонентов.

## Статусы

- **Candidate** — файл найден, но соответствие ранее прошитому образу не доказано.
- **Tested on one device** — задокументировано использование конкретного файла на одной плате и его SHA-256.
- **Reproducible build** — зафиксированы исходники, зависимости, патчи, команды и артефакты для воспроизведения.

Не применяйте статус Tested только на основании строки версии, имени файла или похожих характеристик.

## Где хранить

Текстовые манифесты — `prebuilt/`, история — `changelogs/`; бинарные файлы — GitHub Releases (если разрешено лицензией и происхождением). Пользовательские дампы не публиковать.

## Проверка SHA-256 на Windows

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\\path\\to\\firmware.bin'
```

Должно быть полное совпадение хеша, а не только размера. **Ни одна новая прошивка не считается подтверждённой без реального файла и тестов.**
